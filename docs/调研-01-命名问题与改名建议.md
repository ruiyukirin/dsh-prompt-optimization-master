## 一、结论先行

**一句话：`dsh-prompt-enhance` 这个名字已经彻底不属于我们了——npm（Node 包管理器）上被 `rongxingda` 先占，GitHub 上同名仓库有 9 个，插件市场里有 3 条同名条目。必须改名，而且不能只是"加个后缀凑合"。**

**首选方案（结论）：**

| 项目 | 建议值 | 是否必改 |
|---|---|---|
| npm 包名（安装键） | `@ruiyukirin/dsh-prompt-enhance` | **必改**（不改就发不出去） |
| GitHub 仓库名 + 市场展示名 | `dsh-prompt-enhance-kirin`（备选 `dsh-kirin-prompt-enhance`） | 强烈建议 |

**理由（三条）：**

1. **npm 侧已经堵死。** `dsh-prompt-enhance` 由 `rongxingda` 持有，20 个版本、近 30 天下载 5295 次（来源：`https://registry.npmjs.org/dsh-prompt-enhance`、`https://api.npmjs.org/downloads/point/last-month/dsh-prompt-enhance`）。npm 包名是先到先得、全局唯一，我们不可能用这个名字发布。
2. **`@ruiyukirin` 这个 scope（作用域，即包名前缀命名空间）已经是我们自己的，且现在一个包都没发。** 本机 npm CLI 实测 `npm whoami` 返回 `ruiyukirin`；`maintainer:ruiyukirin` 搜索命中我们自己已发布的 `dsh-douyin-oem-touliu-report`；而 `scope:ruiyukirin` 搜索**命中 0 个包**。也就是说：用 scope 包名既能保留 `dsh-prompt-enhance` 这个搜索关键词，又天然零撞名。
3. **生态里用 scope 包名是主流做法之一。** 市场注册表 4460 个插件里，2314 个登记了 npm 包名，其中 **596 个（25.8%）用的是 `@作者/包名` 的 scope 形式**（来源：本机 `registry.json` 统计，见第六节）。

**不是首选但可用的替代名**：`dsh-prompt-enhance-kirin`、`dsh-kirin-prompt-enhance`、`dsh-draft-rewrite`、`dsh-composer-boost`、`dsh-draftsmith`、`dsh-promptist`、`dsh-enhance-chip`、`dsh-rewrite-chip`、`dsh-prompt-enhance-pro`、`dsh-prompt-clarify`、`dsh-draft-tune` —— 这 11 个在 npm、GitHub、市场**三处全部无占用**（逐个实测，见第五节）。

**已排除的名字**：`dsh-prompt-polish`（npm 被 `gaowei012` 占，GitHub 7 个同名仓库）、`dsh-prompt-refine`（npm 被 `sojo-negai` 占，GitHub 3 个同名）、`dsh-prompt-forge`（npm 可用但 GitHub 已有 2 个同名）、`dsh-prompt-tuner`（npm 可用但 GitHub 已有 1 个同名）。

## 二、更严重的问题：这不只是撞名，是撞功能

撞名只是表症。真正要命的是——**对方的插件和我们做的是同一件事**。

`rongxingda` 的包描述（来源：`https://registry.npmjs.org/dsh-prompt-enhance` 的 `description` 字段，原文）：

> "Prompt enhancement for the dsh web GUI: rewrite the composer draft into a well-structured prompt through the harness LLM service, preview the before/after, then fill back, copy, or undo. Original draft is always preserved."

翻译：**在 DSH 网页版里改写输入框草稿、预览前后对比、填回 / 复制 / 撤销，且始终保留原始草稿。**

对照本插件 `package.json` 第 4 行描述（原文，本机文件 `dsh-prompt-enhance/package.json`）：

> "Prompt enhancement button for the DeepSeek Harness composer: one click rewrites the unsent draft into a clearer, more specific prompt, click again to restore the original. Independent model call that never touches the session log."

翻译：**DSH 输入框的提示词增强按钮，一键把未发送的草稿改写成更清晰具体的提示词，再点一次还原；独立模型调用，不写入会话记录。**

两者是**同一个产品定位**。叠加下面这组事实：

- GitHub 搜索 `dsh-prompt-enhanc in:name fork:true` 命中 **38 个仓库**，其中名字**完全等于** `dsh-prompt-enhance` 的有 **9 个**（7 个原创 + 2 个 fork/派生副本）；
- 名字以 `dsh-prompt-enhanc` 开头的有 **35 个**（来源：`gh api "search/repositories?q=... in:name fork:true"`，翻 3 页取全，2026-10-09 实测）；
- 市场注册表里名字含 `prompt` 且含 `enhanc` 的条目只有 7 条**进了市场**，但 GitHub 上同类仓库有 38 个 —— 说明市场收录远未覆盖这个赛道的全部供给。

**结论：这是个红海中的红海。改名的目标不该只是"避开撞名"，而是"让人一眼认出这不是第 10 个同款"。**

## 六、该不该用 scoped 包名（`@ruiyukirin/xxx`）？

### 6.1 生态实证：scope 包名不是异类，是主流做法之一

来源：本机市场缓存 `registry.json` 的 4460 条 `plugins` 全量统计（2026-10-09）。

| 指标 | 数值 | 占比 |
|---|---|---|
| 插件总数 | 4460 | 100% |
| 登记了 `npm` 字段的条目 | 2314 | 51.9% |
| 未登记 `npm`（走 GitHub / tarball 直装） | 2146 | 48.1% |
| **scope 形式的 npm 包名（`@作者/包名`）** | **596** | **占有 npm 字段条目的 25.8%** |
| 非 scope 的 npm 裸名 | 1718 | 74.2% |

scope 使用量前几名：`@goodandready`(28)、`@weibaohui`(21)、`@mzzsfy`(12)、`@michengai`(11)、`@creait`(9)、`@dennisrongo`(8)、`@hyzyn`(8)、`@duke-dsh-plugins`(8)、`@max-null`(7)、`@linxin666`(7)。

**关键先例**：市场条目 `dsh--prompt--enhance`（owner `sunzhentao`，★4，downloads **790**）的 npm 包名是 **`@lidaxi/prompt-enhance`** —— 仓库名和 npm 包名完全不同，且用的是 scope。这就是"撞名之后用 scope 绕开"的现成范例，来源：市场缓存该条目的 `npm` 字段。

### 6.2 利弊分析

**利（用 scope）：**

1. **零撞名**：`@ruiyukirin/*` 命名空间由我们的 npm 账号独占（`npm whoami` = `ruiyukirin` 实测），别人抢不走。
2. **能保住关键词**：包名尾巴仍可以是 `dsh-prompt-enhance`，安装命令 `dsh plugin add @ruiyukirin/dsh-prompt-enhance` 里"提示词增强"的语义一点没丢。
3. **生态接受度高**：25.8% 的已登记插件都用 scope，装起来没有额外门槛；市场缓存也把 scope 名当 key 正常收录（本机 `discovery-compatibility-v1.json` 的 `entries` 里第一条就是 `@lidaxi/prompt-enhance`）。
4. **未来横向扩展方便**：再出 `@ruiyukirin/dsh-xxx` 时品牌一致。

**弊（用 scope）：**

1. **安装命令变长**：`dsh plugin add @ruiyukirin/dsh-prompt-enhance` 比裸名长一截，用户手打更累、也更容易打错。
2. **必须显式声明公开**：scoped 包发布默认是 **private（私有）**，必须 `npm publish --access public`，否则市场读不到、用户装不了。这是一个**容易踩的发布坑**。
3. **npm 搜索权重略吃亏**：裸名的精确匹配通常排在 scope 名前面（本次实测无法量化这一项，属于经验判断，标注为**未量化**）。
4. **依赖 npm 账号安全**：scope 名下所有包的发布权都系于 `ruiyukirin` 一个账号，账号丢了品牌就丢了（可开 2FA 缓解）。

**`@kirin/dsh-prompt-enhance` 的特别提醒**：实测 npm 返回 404、`scope:kirin` 搜索命中 0 个包，看起来"可用"。但**用户名 scope 需要账号名恰好叫 `kirin`**，本机 npm 登录的是 `ruiyukirin`，不是 `kirin`；npm 上 `kirin` 账号是否已被他人注册**未验证**（该查询需要鉴权，接口返回 401）。所以这个名字**不建议用**，属于"看着空，其实不一定能发"的陷阱。

### 6.3 结论

**用 scope。** 但建议采用"双层命名"：

- **npm 包名（安装键）= `@ruiyukirin/dsh-prompt-enhance`** —— 唯一、可发布、保住关键词。
- **GitHub 仓库名 / 市场展示名 = 换一个不重名的名字** —— 因为市场展示名取自仓库名，继续叫 `dsh-prompt-enhance` 只会让市场出现第 4 条同名条目。

## 七、DSH 生态的既有命名惯例（数据实证）

来源：本机市场缓存 `registry.json` 全量 4460 条统计（2026-10-09）。注意：市场缓存里的 `name` 字段是**仓库名**，不是 npm 包名。

|---|---|
| **`dsh-` 前缀是绝对主流** | 3809 / 4460 = **85.4%** 的条目以 `dsh-` 开头 |
| 名字长度 | 最短 3，最长 61，**平均 17.1 个字符** |
| kebab-case（小写连字符） | 主流；出现下划线/大写的属少数（如 `DSH-better-sidebar`、`Dsh-Prompt-Enhancement`） |
| **重名是常态但应避免** | 4460 条里有 **4167 个不同名字**，**192 组重名** |
| scope 包名占比 | 有 npm 字段的 2314 条中，**596 条（25.8%）**用 scope |
| scope 名与仓库名是否一致 | 596 条 scope 中，**410 条（68.8%）** npm 包名末段与仓库名完全一致；**186 条（31.2%）** 不一致（例：`dsh-plugin#dsh-weather` → `@dennisrongo/dsh-weather`） |

| 大厂/团队做法 | `@deepseek-ai/*`（官方）、`@linxin666/*`（7 个）、`@michengai/*`（11 个）—— **有多个插件的作者几乎都用 scope** |

**推断（非实测）**：`prompt` 在第二词段只出现 32 次，说明"prompt-xxx"这个命名路线在 DSH 生态里并不拥挤；拥挤的是**具体语义**——所有人都叫 `dsh-prompt-enhance(r)`。所以改名的方向应该是**换语义角度**（草稿 / 输入框 / 重写），而不是继续在 `prompt-enhance` 上做后缀文章。

## 八、首选方案与执行清单

### 8.1 首选方案（明确结论）

**方案：双层命名**

```
npm 包名（安装键，必改）：  @ruiyukirin/dsh-prompt-enhance
GitHub 仓库名（建议改）：    dsh-prompt-enhance-kirin
市场展示名（跟随仓库名）：    dsh-prompt-enhance-kirin
用户看到的安装命令：         dsh plugin --profile web add @ruiyukirin/dsh-prompt-enhance
```

**为什么这样组合：**

1. npm 侧用 scope 兜底 —— 唯一、可发布、保留 `dsh-prompt-enhance` 关键词，且 scope 已被我们自己的账号持有（实测）。
2. GitHub / 市场侧换名 —— 市场有 3 条同名，加进去就是第 4 条；换名后既唯一，又满足 `dsh-` 前缀 + Kirin 标记。
3. **名字仍是"自解释"的** —— 用户看到 `dsh-prompt-enhance-kirin` 就知道它是提示词增强插件、作者是 Kirin，不需要额外教育成本。

**备选方案 B（最小改动）**：只改 npm 包名为 `@ruiyukirin/dsh-prompt-enhance`，GitHub 仓库仍叫 `dsh-prompt-enhance`（实测 404，可用）。
- 优点：改动面最小，文档/路由里的 `dsh-prompt-enhance` 字样全都不用动。
- 缺点：市场会出现**第 4 条**同名条目；GitHub 搜索永远被 `rongxingda`(★10) 压着；"用户装错"的风险只解决了市场安装命令那一半（因为市场还有 `zzy6-a`、`ZiYuan258` 两个同名条目在抢注意力）。

**推荐选 A。** 理由一句话：撞名这件事，只解决一半 = 没解决。
