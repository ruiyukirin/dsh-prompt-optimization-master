## 一、`conversation.input.right` 插槽交给占用者的东西

注册后组件收到的 props（实测，非猜测）：

```
useSessions  useSessionStatus  usePanelInfo  useWorkspaces  useResource
useSessionRetainInfo  sessionId  inputActions  useSession  useConversation
useInput  useTrajectory  useChat  useProjection  renderFactorySlot
（+ 自己 inject() 里声明的字段）
```

### 读草稿 —— `useInput`

是个选择器钩子（SnapshotSelectorHook），`useInput(s => s)` 返回的 InputState：

```json
{
  "draft": "",            // ← 草稿纯文本，就是它
  "attachmentIds": [],
  "draftRev": 109,        // 草稿版本号，可用于变更检测
  "phase": "plain",       // 输入框阶段
  "occurrences": [],
  "queue": []
}
```

取草稿：`useInput(s => s.draft)` → 字符串。
监听变化：`useInput(s => s.draftRev)`。

### 写回草稿 —— `inputActions`

方法清单（实测）：

| 方法 | 用途 |
|---|---|
| `setDraft` | **写回草稿文本**（优化结果就靠它） |
| `insertText` | 在光标处插入文本 |
| `captureInsertion` | 捕获插入点 |
| `submit` | 直接提交 |
| `addAttachments` / `removeAttachment` / `pruneAttachments` | 附件管理 |

## 二、两个必须记住的环境事实

### 1. 客户端半会热更新，宿主半不会

- 改 `client/client.js` → HMR 自动推到运行中的页面，**不用刷新**，`apply` 会重跑。
- 改 `dsh/index.js` → **ESM 模块被缓存了**，禁用/启用插件也不会重新导入，
  要 DSH 重启才生效。这是开发节奏上的硬约束。

### 2. 桌面版界面跑在自定义协议上

DSH 桌面版的渲染进程用 `dsh-app://app` 协议加载界面（进程命令行可见
`--standard-schemes=dsh-app --fetch-schemes=dsh-app`）。
所以客户端里的 `fetch('/相对路径')` 打到的是 **自定义协议处理器**，
不一定转发到宿主的 HTTP 服务 —— 实测走 HTTP 路由回报失败。

### 3. 无头调试通道

拿不到浏览器控制台，但可以把数据写进 `localStorage`，
再从磁盘上的 leveldb 直接读：

```

```

探针就是这样把契约捞出来的。这个方法以后调 UI 都能用。
